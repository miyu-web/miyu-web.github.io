UnityURP-LitShader详解

更新于2026-03-15
|总字数:18.4k|阅读时长:91分钟|浏览量:

前言

 Unity URP Lit Shader是基于物理渲染的Shader，但Unity对其做了一些修改，不完全按照BRDF公式计算，很多都做了拟合曲线，这样就导致UnityURP的LitShader与实际的物理效果材质有所偏差。Unity这样做的目的是对其进行优化，以便能够在移动端高性能运行。

  • _WorkflowMode：工作流模式，关联关键字 _SPECULAR_SETUP。

    • 类型范围：float类型，数值为0 或 1。
    • 数值含义：
      • 0：使用高光工作流，脚本开启关键字 _SPECULAR_SETUP。
      • 1：使用金属工作流，脚本关闭关键字 _SPECULAR_SETUP。

  • _BaseMap：主帖图。

    • 类型：2D，默认白色贴图。
    • 数值含义：是我们经常使用的albedo贴图，代码物体的反照率颜色，通俗讲就是物体本身的基础色。

  • _BaseColor：主颜色。

    • 类型：Color，默认白色。
    • 数值含义：用于调节反照率，一般与采样 _BaseMap 后的颜色进行相乘获取最终的反照率。

  • _Cutoff：用于透明度裁剪。

    • 数值范围：float 类型，范围0~1。
    • 数值含义：在需要AlphaTest中可以作为参数使用，因为不透明物体想要做出镂空或者溶解这种效果的话，只能使用透明裁剪。

  • _Smoothness：光滑度调节值。

    • 类型范围：float类型，单位0~1。
    • 数值含义：控制光滑度的强度。

  • _SmoothnessTextureChannel：光滑度数值存放在哪张贴图的通道中，关联的Shader关键字 _SMOOTHNESS_TEXTURE_ALBEDO_CHANNEL_A。

    • 类型范围：float类型，数值为0 或 1。

    • 数值含义：

      • 0：贴图的光滑度存在于金属度贴图或者高光贴图的Alpha通道中，脚本关闭关键字 _SMOOTHNESS_TEXTURE_ALBEDO_CHANNEL_A。
      • 1：贴图的光滑度存在于 _BaseMap 贴图的Alpha通道中，脚本开启关键字 _SMOOTHNESS_TEXTURE_ALBEDO_CHANNEL_A。

      /// <summary>
/// Retrieves the alpha channel used for smoothness.
/// </summary>
/// <param name="material"></param>
/// <returns>The Alpha channel used for Smoothness.</returns>
public static SmoothnessMapChannel GetSmoothnessMapChannel(Material material)
{
    int ch = (int)material.GetFloat("_SmoothnessTextureChannel");
    if (ch == (int)SmoothnessMapChannel.AlbedoAlpha)
        return SmoothnessMapChannel.AlbedoAlpha;

    return SmoothnessMapChannel.SpecularMetallicAlpha;
}

      定位可以看到这个变量用在了 LightingPhysicallyBased 函数中。
      half3 LightingPhysicallyBased(BRDFData brdfData, BRDFData brdfDataClearCoat,
half3 lightColor, half3 lightDirectionWS, half lightAttenuation,
half3 normalWS, half3 viewDirectionWS,
half clearCoatMask, bool specularHighlightsOff)
{
    half NdotL = saturate(dot(normalWS, lightDirectionWS));
    half3 radiance = lightColor * (lightAttenuation * NdotL);

    half3 brdf = brdfData.diffuse;
#ifndef _SPECULARHIGHLIGHTS_OFF
    [branch] if (!specularHighlightsOff)
    {
        brdf += brdfData.specular * DirectBRDFSpecular(brdfData, normalWS, lightDirectionWS, viewDirectionWS);

#if defined(_CLEARCOAT) || defined(_CLEARCOATMAP)
        // Clear coat evaluates the specular a second timw and has some common terms with the base specular.
        // We rely on the compiler to merge these and compute them only once.
        half brdfCoat = kDielectricSpec.r * DirectBRDFSpecular(brdfDataClearCoat, normalWS, lightDirectionWS, viewDirectionWS);

            // Mix clear coat and base layer using khronos glTF recommended formula
            // https://github.com/KhronosGroup/glTF/blob/master/extensions/2.0/Khronos/KHR_materials_clearcoat/README.md
            // Use NoV for direct too instead of LoH as an optimization (NoV is light invariant).
            half NoV = saturate(dot(normalWS, viewDirectionWS));
            // Use slightly simpler fresnelTerm (Pow4 vs Pow5) as a small optimization.
            // It is matching fresnel used in the GI/Env, so should produce a consistent clear coat blend (env vs. direct)
            half coatFresnel = kDielectricSpec.x + kDielectricSpec.a * Pow4(1.0 - NoV);

        brdf = brdf * (1.0 - clearCoatMask * coatFresnel) + brdfCoat * clearCoatMask;
#endif // _CLEARCOAT
    }
#endif // _SPECULARHIGHLIGHTS_OFF

    return brdf * radiance;
}

      可以看到 LightingPhysicallyBased 中又判断了关键字 _SPECULARHIGHLIGHTS_OFF 的定义，然后还使用了布尔变量 specularHighlightsOff，简直是脱裤子放屁多此一举，不知道Unity为什么要这么做。

      half3 GlossyEnvironmentReflection(half3 reflectVector, float3 positionWS, half perceptualRoughness, half occlusion, float2 normalizedScreenSpaceUV)
{
#if !defined(_ENVIRONMENTREFLECTIONS_OFF)
    half3 irradiance;

#if defined(_REFLECTION_PROBE_BLENDING) || USE_FORWARD_PLUS
    irradiance = CalculateIrradianceFromReflectionProbes(reflectVector, positionWS, perceptualRoughness, normalizedScreenSpaceUV);
#else
#ifdef _REFLECTION_PROBE_BOX_PROJECTION
    reflectVector = BoxProjectedCubemapDirection(reflectVector, positionWS, unity_SpecCube0_ProbePosition, unity_SpecCube0_BoxMin, unity_SpecCube0_BoxMax);
#endif // _REFLECTION_PROBE_BOX_PROJECTION
    half mip = PerceptualRoughnessToMipmapLevel(perceptualRoughness);
    half4 encodedIrradiance = half4(SAMPLE_TEXTURECUBE_LOD(unity_SpecCube0, samplerunity_SpecCube0, reflectVector, mip));

    irradiance = DecodeHDREnvironment(encodedIrradiance, unity_SpecCube0_HDR);
#endif // _REFLECTION_PROBE_BLENDING

#else

half3 GlossyEnvironmentReflection(half3 reflectVector, half perceptualRoughness, half occlusion)
{
#if !defined(_ENVIRONMENTREFLECTIONS_OFF)
    half3 irradiance;
    half mip = PerceptualRoughnessToMipmapLevel(perceptualRoughness);
    half4 encodedIrradiance = half4(SAMPLE_TEXTURECUBE_LOD(unity_SpecCube0, samplerunity_SpecCube0, reflectVector, mip));

    irradiance = DecodeHDREnvironment(encodedIrradiance, unity_SpecCube0_HDR);

    return irradiance * occlusion;
#else

    return _GlossyEnvironmentColor.rgb * occlusion;
#endif // _ENVIRONMENTREFLECTIONS_OFF
}

      两个方法都很明显，是对环境高光反射的计算，而且它们在没有开启环境反射的情况下，都返回内置的环境高光颜色 _GlossyEnvironmentColor。而开启环境高光，他们的区别就在于第一个函数多了反射探针的计算。

      • USE_FORWARD_PLUS 是前向渲染预定义，它的定义代码如下：
        #if defined(_FORWARD_PLUS)
#define _ADDITIONAL_LIGHTS 1
#undef _ADDITIONAL_LIGHTS_VERTEX
#define USE_FORWARD_PLUS 1
#else
#define USE_FORWARD_PLUS 0
#endif
      • _REFLECTION_PROBE_BLENDING：反射探针混合关键字，作用是多个反射探针叠加。
        • CalculateIrradianceFromReflectionProbes：计算混合后的反射探针辐照度。
      • _REFLECTION_PROBE_BOX_PROJECTION：反射探针盒型投影关键字，作用是但反射探针采样。
        • BoxProjectedCubemapDirection：修正反射方向向量，让反射探针的采样结果贴合场景中的 “盒子” 范围，避免反射探针在盒子外采样错误，提升反射的空间准确性。
        • unity_SpecCube0_ProbePosition：第一个反射探针的世界空间位置。
        • unity_SpecCube0_BoxMin/BoxMax：反射探针盒式投影的最小 / 最大边界。
      • PerceptualRoughnessToMipmapLevel：将感知粗糙度转换为立方体贴图的 Mip 层级，粗糙度越高，Mip 层级越大，采样越模糊的层级，符合物理规律。
      • SAMPLE_TEXTURECUBE_LOD： 采样立方体贴图（反射探针的纹理 unity_SpecCube0 ），指定 Mip 层级 mip，得到编码后的 HDR 反射颜色。
      • DecodeHDREnvironment：解码 HDR 格式的环境色（Unity 反射探针默认用 RGBM 等格式压缩 HDR 数据），unity_SpecCube0_HDR 是解码所需的 HDR 参数。

internal static void SetupMaterialBlendModeInternal(Material material, out int automaticRenderQueue)
{
    if (material == null)
        throw new ArgumentNullException("material");

    bool alphaClip = false;
    if (material.HasProperty(Property.AlphaClip))
        alphaClip = material.GetFloat(Property.AlphaClip) >= 0.5;
    CoreUtils.SetKeyword(material, ShaderKeywordStrings._ALPHATEST_ON, alphaClip);

    // default is to use the shader render queue
    int renderQueue = material.shader.renderQueue;
    material.SetOverrideTag("RenderType", "");      // clear override tag
    if (material.HasProperty(Property.SurfaceType))
    {
        SurfaceType surfaceType = (SurfaceType)material.GetFloat(Property.SurfaceType);
        bool zwrite = false;
        CoreUtils.SetKeyword(material, ShaderKeywordStrings._SURFACE_TYPE_TRANSPARENT, surfaceType == SurfaceType.Transparent);
        bool alphaToMask = false;
        if (surfaceType == SurfaceType.Opaque)
        {
            if (alphaClip)
            {
                renderQueue = (int)RenderQueue.AlphaTest;
                material.SetOverrideTag("RenderType", "TransparentCutout");
                alphaToMask = true;
            }
            else
            {
                renderQueue = (int)RenderQueue.Geometry;
                material.SetOverrideTag("RenderType", "Opaque");
            }

            SetMaterialSrcDstBlendProperties(material, UnityEngine.Rendering.BlendMode.One, UnityEngine.Rendering.BlendMode.Zero);
            zwrite = true;
            material.DisableKeyword(ShaderKeywordStrings._ALPHAPREMULTIPLY_ON);
            material.DisableKeyword(ShaderKeywordStrings._ALPHAMODULATE_ON);
        }
        else // SurfaceType Transparent
        {
            BlendMode blendMode = (BlendMode)material.GetFloat(Property.BlendMode);

            var srcBlendRGB = UnityEngine.Rendering.BlendMode.One;
            var dstBlendRGB = UnityEngine.Rendering.BlendMode.OneMinusSrcAlpha;
            var srcBlendA = UnityEngine.Rendering.BlendMode.One;
            var dstBlendA = UnityEngine.Rendering.BlendMode.OneMinusSrcAlpha;

            // Specific Transparent Mode Settings
            switch (blendMode)
            {
                // srcRGB * srcAlpha + dstRGB * (1 - srcAlpha)
                // preserve spec:
                // srcRGB * (<in shader> ? 1 : srcAlpha) + dstRGB * (1 - srcAlpha)
                case BlendMode.Alpha:
                    srcBlendRGB = UnityEngine.Rendering.BlendMode.SrcAlpha;
                    dstBlendRGB = UnityEngine.Rendering.BlendMode.OneMinusSrcAlpha;
                    srcBlendA = UnityEngine.Rendering.BlendMode.One;
                    dstBlendA = dstBlendRGB;
                    break;

                // srcRGB < srcAlpha, (alpha multiplied in asset)
                // srcRGB * 1 + dstRGB * (1 - srcAlpha)
                case BlendMode.Premultiply:
                    srcBlendRGB = UnityEngine.Rendering.BlendMode.One;
                    dstBlendRGB = UnityEngine.Rendering.BlendMode.OneMinusSrcAlpha;
                    srcBlendA = srcBlendRGB;
                    dstBlendA = dstBlendRGB;
                    break;

                // srcRGB * srcAlpha + dstRGB * 1, (alpha controls amount of addition)
                // preserve spec:
                // srcRGB * (<in shader> ? 1 : srcAlpha) + dstRGB * (1 - srcAlpha)
                case BlendMode.Additive:
                    srcBlendRGB = UnityEngine.Rendering.BlendMode.SrcAlpha;
                    dstBlendRGB = UnityEngine.Rendering.BlendMode.One;
                    srcBlendA = UnityEngine.Rendering.BlendMode.One;
                    dstBlendA = dstBlendRGB;
                    break;

                // srcRGB * 0 + dstRGB * srcRGB
                // in shader alpha controls amount of multiplication, lerp(1, srcRGB, srcAlpha)
                // Multiply affects color only, keep existing alpha.
                case BlendMode.Multiply:
                    srcBlendRGB = UnityEngine.Rendering.BlendMode.DstColor;
                    dstBlendRGB = UnityEngine.Rendering.BlendMode.Zero;
                    srcBlendA = UnityEngine.Rendering.BlendMode.Zero;
                    dstBlendA = UnityEngine.Rendering.BlendMode.One;
                    break;
            }

            // Lift alpha multiply from ROP to shader by setting pre-multiplied _SrcBlend mode.
            // The intent is to do different blending for diffuse and specular in shader.
            // ref: http://advances.realtimerendering.com/other/2016/naughty_dog/NaughtyDog_TechArt_Final.pdf
            bool preserveSpecular = (material.HasProperty(Property.BlendModePreserveSpecular) &&
                                        material.GetFloat(Property.BlendModePreserveSpecular) > 0) &&
                                    blendMode != BlendMode.Multiply && blendMode != BlendMode.Premultiply;
            if (preserveSpecular)
            {
                srcBlendRGB = UnityEngine.Rendering.BlendMode.One;
            }

            // When doing off-screen transparency accumulation, we change blend factors as described here: https://developer.nvidia.com/gpugems/GPUGems3/gpugems3_ch23.html
            bool offScreenAccumulateAlpha = false;
            if (offScreenAccumulateAlpha)
                srcBlendA = UnityEngine.Rendering.BlendMode.Zero;

            SetMaterialSrcDstBlendProperties(material, srcBlendRGB, dstBlendRGB, // RGB
                srcBlendA, dstBlendA); // Alpha

            CoreUtils.SetKeyword(material, ShaderKeywordStrings._ALPHAPREMULTIPLY_ON, preserveSpecular);
            CoreUtils.SetKeyword(material, ShaderKeywordStrings._ALPHAMODULATE_ON, blendMode == BlendMode.Multiply);

            // General Transparent Material Settings
            material.SetOverrideTag("RenderType", "Transparent");
            zwrite = false;
            renderQueue = (int)RenderQueue.Transparent;
        }

        if (material.HasProperty(Property.AlphaToMask))
        {
            material.SetFloat(Property.AlphaToMask, alphaToMask ? 1.0f : 0.0f);
        }

        // check for override enum
        if (material.HasProperty(Property.ZWriteControl))
        {
            var zwriteControl = (UnityEditor.Rendering.Universal.ShaderGraph.ZWriteControl)material.GetFloat(Property.ZWriteControl);
            if (zwriteControl == UnityEditor.Rendering.Universal.ShaderGraph.ZWriteControl.ForceEnabled)
                zwrite = true;
            else if (zwriteControl == UnityEditor.Rendering.Universal.ShaderGraph.ZWriteControl.ForceDisabled)
                zwrite = false;
        }
        SetMaterialZWriteProperty(material, zwrite);
        material.SetShaderPassEnabled("DepthOnly", zwrite);
    }
    else
    {
        // no surface type property -- must be hard-coded by the shadergraph,
        // so ensure the pass is enabled at the material level
        material.SetShaderPassEnabled("DepthOnly", true);
    }

    // must always apply queue offset, even if not set to material control
    if (material.HasProperty(Property.QueueOffset))
        renderQueue += (int)material.GetFloat(Property.QueueOffset);

    automaticRenderQueue = renderQueue;
}

{

    outSurfaceData.alpha = Alpha(albedoAlpha.a, _BaseColor, _Cutoff);

    half4 specGloss = SampleMetallicSpecGloss(uv, albedoAlpha.a);
    outSurfaceData.albedo = albedoAlpha.rgb * _BaseColor.rgb;
    outSurfaceData.albedo = AlphaModulate(outSurfaceData.albedo, outSurfaceData.alpha);

#if _SPECULAR_SETUP
    outSurfaceData.metallic = half(1.0);
    outSurfaceData.specular = specGloss.rgb;
#else
    outSurfaceData.metallic = specGloss.r;
    outSurfaceData.specular = half3(0.0, 0.0, 0.0);
#endif

    outSurfaceData.smoothness = specGloss.a;
    outSurfaceData.normalTS = SampleNormal(uv, TEXTURE2D_ARGS(_BumpMap, sampler_BumpMap), _BumpScale);
    outSurfaceData.occlusion = SampleOcclusion(uv);
    outSurfaceData.emission = SampleEmission(uv, _EmissionColor.rgb, TEXTURE2D_ARGS(_EmissionMap, sampler_EmissionMap));

#if defined(_CLEARCOAT) || defined(_CLEARCOATMAP)
    half2 clearCoat = SampleClearCoat(uv);
    outSurfaceData.clearCoatMask       = clearCoat.r;
    outSurfaceData.clearCoatSmoothness = clearCoat.g;
#else
    outSurfaceData.clearCoatMask       = half(0.0);
    outSurfaceData.clearCoatSmoothness = half(0.0);
#endif

#if defined(_DETAIL)
    half detailMask = SAMPLE_TEXTURE2D(_DetailMask, sampler_DetailMask, uv).a;
    float2 detailUv = uv * _DetailAlbedoMap_ST.xy + _DetailAlbedoMap_ST.zw;
    outSurfaceData.albedo = ApplyDetailAlbedo(detailUv, outSurfaceData.albedo, detailMask);
    outSurfaceData.normalTS = ApplyDetailNormal(detailUv, outSurfaceData.normalTS, detailMask);

定义采样金属/高光工作流的高光函数

half4 SampleMetallicSpecGloss(float2 uv, half albedoAlpha)
{
    half4 specGloss;

#ifdef _METALLICSPECGLOSSMAP
    specGloss = half4(SAMPLE_METALLICSPECULAR(uv));
    #ifdef _SMOOTHNESS_TEXTURE_ALBEDO_CHANNEL_A
        specGloss.a = albedoAlpha * _Smoothness;
    #else
        specGloss.a *= _Smoothness;
    #endif
#else // _METALLICSPECGLOSSMAP
    #if _SPECULAR_SETUP
        specGloss.rgb = _SpecColor.rgb;
    #else
        specGloss.rgb = _Metallic.rrr;
    #endif

    #ifdef _SMOOTHNESS_TEXTURE_ALBEDO_CHANNEL_A
        specGloss.a = albedoAlpha * _Smoothness;
    #else
        specGloss.a = _Smoothness;
    #endif
#endif

    return specGloss;
}
  • uv：输入一个采样uv，一般就是模型的uv。
  • albedoAlpha: albedo贴图的Alpha数值，这个数值一定是albedo贴图的，不能做预处理，比如albedo*_BaseColor，这是不可以的。但如果是自定义，那就不用考虑这种问题了。
    albedoAlpha = SAMPLE_TEXTURE2D(_BaseMap,sampler_BaseMap,i.uv).a;

 在这个函数中，首先定义了一个变量 specGloss ，然后分为两种情况：

  1. 材质面板赋予了金属/高光工作流的高光贴图：
  • 先采样贴图，SAMPLE_METALLICSPECULAR 会根据对应的工作流返回对应的贴图的颜色，则获得了 specGloss 的rgb颜色，存放高光颜色。
  • 然后获取光滑度，光滑度存放在 specGloss 的alpha通道中，分为两种情况：
    1. 光滑度数值贴图来自 albedoAlpha ，则返回 albedoAlpha*调节参数（即_Smoothness）。
    2. 光滑度数值贴图来自高光贴图 ，则数值就是采样好并存储好的 specGloss.a ，直接返回 specGloss.a*调节参数（即_Smoothness）。
  1. 材质面板未赋予金属/高光工作流的高光贴图：
  • 先获取高光颜色，高光工作流定义了 _SpecColor 高光颜色属性，直接赋值即可，但是金属工作流不存在 _SpecColor 属性一说，直接赋值为 _Metallic（金属强度调节参数） 的灰度颜色。
  • 然后获取光滑度，光滑度存放在 specGloss 的alpha通道中，分为两种情况：
    1. 光滑度数值贴图来自 albedoAlpha ，则返回 albedoAlpha*调节参数（即_Smoothness）。
    2. 因为没有金属/高光工作流的高光贴图了，因此如果不是来自albedo贴图的alpha通道的话，直接返回 _Smoothness（光滑度调节参数）。

     函数中分为了有遮蔽贴图和没有遮蔽贴图两种情况。所谓遮蔽就是物体自遮挡产生的暗部区域，也叫做Ao。因为实时计算不可能真的去计算物体自身的遮挡关系，这太消耗性能了，所以实时遮蔽都是采用一张遮罩图作为遮蔽区域的遮罩。数值越靠近0，表示这里暗部更多，越靠近1，表示这里越没有自遮挡。

  • 🐍 LerpWhiteTo函数是什么？ 
    real LerpWhiteTo(real b, real t)
{
    real oneMinusT = 1.0 - t;
    return oneMinusT + b * t;
}

    这个函数翻译即为”从白色插值到”，我们可以转换一下公式就知道它其实就是一个 lerp 函数而已：$1-t+b\times t = 1+(b-1)\times t = lerp(1,b,t)$

  • 🐍 为什么要使用LerpWhiteTo函数？  我们知道 LerpWhiteTo 不过是一个封装的从1插值到目标值的函数，回到Shader代码，我们实际可以将其转换成直观的表示：
    half SampleOcclusion(float2 uv)
{
    #ifdef _OCCLUSIONMAP
        half occ = SAMPLE_TEXTURE2D(_OcclusionMap, sampler_OcclusionMap, uv).g;
        return lerp(1.0,occ, _OcclusionStrength);
    #else
        return half(1.0);
    #endif
}
     因为我们拥有 _OcclusionStrength 强度调节属性，那么当 _OcclusionStrength 为0时，则应该没有遮蔽，反之为1时则根据贴图的遮蔽区域进行设置。
     我们放到宏观来看，遮蔽贴图一定是有的地方没有遮蔽，那么那部分贴图区域就为1，有的地方有遮蔽，那部分贴图区域为0。
    • 当 occ 为1时，不管如何调节 _OcclusionStrength 都为1，这样就保证了这部分区域是没有遮蔽的。
    • 但 ooc 为0时，那么返回的遮蔽强度将会是 1.0-_OcclusionStrength 强度，则即使参数越大，那么这个区域就越暗，反之越亮。

      #if defined(_ALPHAMODULATE_ON)

        fogFactor = ComputeFogFactor(vertexInput.positionCS.z);
    #endif

    output.normalWS = normalInput.normalWS;
#if defined(REQUIRES_WORLD_SPACE_TANGENT_INTERPOLATOR) || defined(REQUIRES_TANGENT_SPACE_VIEW_DIR_INTERPOLATOR)
    real sign = input.tangentOS.w * GetOddNegativeScale();

    output.tangentWS = tangentWS;
#endif

    half3 viewDirTS = GetViewDirectionTangentSpace(tangentWS, output.normalWS, viewDirWS);
    output.viewDirTS = viewDirTS;
#endif

#ifdef DYNAMICLIGHTMAP_ON
    output.dynamicLightmapUV = input.dynamicLightmapUV.xy * unity_DynamicLightmapST.xy + unity_DynamicLightmapST.zw;

      // Return view direction in tangent space, make sure tangentWS.w is already multiplied by GetOddNegativeScale()
  half3 GetViewDirectionTangentSpace(half4 tangentWS, half3 normalWS, half3 viewDirWS)
  {
      // must use interpolated tangent, bitangent and normal before they are normalized in the pixel shader.
      half3 unnormalizedNormalWS = normalWS;
      const half renormFactor = 1.0 / length(unnormalizedNormalWS);

      // use bitangent on the fly like in hdrp
      // IMPORTANT! If we ever support Flip on double sided materials ensure bitangent and tangent are NOT flipped.
      half crossSign = (tangentWS.w > 0.0 ? 1.0 : -1.0); // we do not need to multiple GetOddNegativeScale() here, as it is done in vertex shader
      half3 bitang = crossSign * cross(normalWS.xyz, tangentWS.xyz);

      half3 WorldSpaceNormal = renormFactor * normalWS.xyz;       // we want a unit length Normal Vector node in shader graph

      // to preserve mikktspace compliance we use same scale renormFactor as was used on the normal.
      // This is explained in section 2.2 in "surface gradient based bump mapping framework"
      half3 WorldSpaceTangent = renormFactor * tangentWS.xyz;
      half3 WorldSpaceBiTangent = renormFactor * bitang;

      half3x3 tangentSpaceTransform = half3x3(WorldSpaceTangent, WorldSpaceBiTangent, WorldSpaceNormal);
      half3 viewDirTS = mul(tangentSpaceTransform, viewDirWS);

      return viewDirTS;
  }

     DecalSurfaceData decalSurfaceData;
     DECODE_FROM_DBUFFER(DBuffer, decalSurfaceData);

     baseColor.xyz = baseColor.xyz * decalSurfaceData.baseColor.w + decalSurfaceData.baseColor.xyz;

        🐍 为什么两种工作流的计算看起来不太一样？

        首先我们要明确一个前提：材质的总反射能量=漫反射能量+镜面反射能量。
        这两种工作流的差异，本质是用不同的参数体系来分配这两部分能量，最终实现相同的物理效果，但适配不同的美术调优习惯。
        正因为体系不同，导致了反射分量计算逻辑的差异：

        • 金属度工作流：用 metallic 参数来约束漫反射与镜面反射的分配（金属无漫反射）。
        • 高光工作流：用 specular 的亮度来分配能量（高光越亮，镜面反射率越高，漫反射越少）。

          bedfDiffuse计算差异：

        金属度工作流：brdfDiffuse = albedo × lerp(0.96, 0.0, metallic);

        • 强制金属无漫反射（真实世界中金属的漫反射趋近于 0，所有反射都是镜面反射），而非金属保留 96% 的漫反射能量（符合 4% 基础镜面反射率的物理规律）。

        高光工作流：brdfDiffuse = albedo × Luminance(specular);

        • 让美术直接通过高光色控制反射能量分配，高光色越亮（反射率越高），漫反射就越少，无需区分 “金属 / 非金属”，适配需要精准调高光颜色的场景（比如彩色高光的塑料玩具）。

          bedfSpecular计算差异：

        金属度工作流：brdfSpecular = lerp(kDieletricSpec.rgb, albedo, metallic);

        • 非金属（ metallic=0 ）时，镜面反射使用中性灰，符合物理，不需要美术手动调节；金属（ metallic=1 ）时，镜面反射色等于基础色（真实金属的镜面反射就是自身颜色，比如黄金的高光也是金色）；半金属线性插值过渡，保证视觉自然。

        高光工作流：brdfDiffuse = albedo × Luminance(specular);

        • 把高光色的控制权完全交给美术，想让高光偏红就设 specular=(1,0,0)，想让高光偏蓝就设 specular=(0,0,1)，无需受 “金属 / 非金属” 的物理规则约束，适配非写实风格（卡通、奇幻材质）或需要特殊高光的写实场景（比如带彩色高光的车漆）。

      half3 SubtractDirectMainLightFromLightmap(Light mainLight, half3 normalWS, half3 bakedGI)
{
    // Let's try to make realtime shadows work on a surface, which already contains
    // baked lighting and shadowing from the main sun light.
    // Summary:
    // 1) Calculate possible value in the shadow by subtracting estimated light contribution from the places occluded by realtime shadow:
    //      a) preserves other baked lights and light bounces
    //      b) eliminates shadows on the geometry facing away from the light
    // 2) Clamp against user defined ShadowColor.
    // 3) Pick original lightmap value, if it is the darkest one.


    // 1) Gives good estimate of illumination as if light would've been shadowed during the bake.
    // We only subtract the main direction light. This is accounted in the contribution term below.
    half shadowStrength = GetMainLightShadowStrength();
    half contributionTerm = saturate(dot(mainLight.direction, normalWS));
    half3 lambert = mainLight.color * contributionTerm;
    half3 estimatedLightContributionMaskedByInverseOfShadow = lambert * (1.0 - mainLight.shadowAttenuation);
    half3 subtractedLightmap = bakedGI - estimatedLightContributionMaskedByInverseOfShadow;

    // 2) Allows user to define overall ambient of the scene and control situation when realtime shadow becomes too dark.
    half3 realtimeShadow = max(subtractedLightmap, _SubtractiveShadowColor.xyz);
    realtimeShadow = lerp(bakedGI, realtimeShadow, shadowStrength);

    // 3) Pick darkest color
    return min(bakedGI, realtimeShadow);
}
      🐍 为什么要混合？

      该函数通过从烘焙光照中扣除 “本应被实时阴影遮挡的主光源贡献”，并结合自定义的阴影颜色做限制，最终选择 “烘焙值” 和 “修正后实时阴影值” 中更暗的结果，实现烘焙光照与实时阴影的自然融合。

      核心解决的问题：
      如果场景烘焙了主光源（比如太阳光）的光照，但运行时需要动态物体投射实时阴影到烘焙表面，直接叠加实时阴影会导致 “烘焙亮区被实时阴影完全覆盖”（过暗），该函数通过精准扣除主光源贡献，保留烘焙的间接光 / 其他光源，让实时阴影更自然。

      AI解释如下：

          half3 SubtractDirectMainLightFromLightmap(Light mainLight, half3 normalWS, half3 bakedGI)
    {
        // ========== 步骤1：计算“应扣除的主光源贡献”（模拟实时阴影遮挡） ==========
        // 1.1 获取用户设置的主光源阴影强度（0=无实时阴影，1=完全生效）
        half shadowStrength = GetMainLightShadowStrength();
        
        // 1.2 计算“表面朝向与主光源的夹角贡献”：仅向光面（dot>0）才扣除主光源，背光面不处理
        // saturate：将结果限制在0~1（避免dot为负时出现错误扣除）
        half contributionTerm = saturate(dot(mainLight.direction, normalWS));
        
        // 1.3 计算主光源对当前像素的兰伯特光照贡献（基础漫反射模型）
        half3 lambert = mainLight.color * contributionTerm;
        
        // 1.4 计算“本应被实时阴影遮挡的主光源贡献”：
        // (1 - shadowAttenuation)：阴影区域该值=1（完全遮挡），无阴影区域=0（不遮挡）
        // 最终：阴影区 = 主光源贡献 × 1（扣除全部），无阴影区 = 主光源贡献 × 0（不扣除）
        half3 estimatedLightContributionMaskedByInverseOfShadow = lambert * (1.0 - mainLight.shadowAttenuation);
        
        // 1.5 从烘焙光照中扣除上述贡献：得到“模拟烘焙时就有实时阴影”的光照值
        // 保留了烘焙的间接光、其他光源，仅扣除主光源的阴影部分
        half3 subtractedLightmap = bakedGI - estimatedLightContributionMaskedByInverseOfShadow;

        // ========== 步骤2：限制阴影过暗 + 混合阴影强度 ==========
        // 2.1 用用户自定义阴影色限制：避免扣除后过黑（比如阴影区不能比_SubtractiveShadowColor更暗）
        half3 realtimeShadow = max(subtractedLightmap, _SubtractiveShadowColor.xyz);
        
        // 2.2 按阴影强度混合“原始烘焙值”和“修正后阴影值”：shadowStrength=0时完全用烘焙值
        realtimeShadow = lerp(bakedGI, realtimeShadow, shadowStrength);

        // ========== 步骤3：选择更暗的值（保证阴影只暗不亮，符合物理） ==========
        // min：如果修正后的阴影值比烘焙值亮，就用烘焙值；否则用阴影值
        return min(bakedGI, realtimeShadow);
    }

      half3 normalWS, half3 viewDirectionWS, float2 normalizedScreenSpaceUV)

      half3 color = EnvironmentBRDF(brdfData, indirectDiffuse, indirectSpecular, fresnelTerm);

      }

      // TODO: "grazing term" causes problems on full roughness

      // Smooth surface & "ambiguous" lighting
      // NOTE: fresnelTerm (above) is pow4 instead of pow5, but should be ok as blend weight.
      half coatFresnel = kDielectricSpec.x + kDielectricSpec.a * fresnelTerm;
      return (color * (1.0 - coatFresnel * clearCoatMask) + coatColor) * occlusion;
  #else

  #endif
  }

 核心还是要看主函数：

half3 LightingPhysicallyBased(BRDFData brdfData, BRDFData brdfDataClearCoat,
    half3 lightColor, half3 lightDirectionWS, half lightAttenuation,
    half3 normalWS, half3 viewDirectionWS,
    half clearCoatMask, bool specularHighlightsOff)
{
    half NdotL = saturate(dot(normalWS, lightDirectionWS));
    half3 radiance = lightColor * (lightAttenuation * NdotL);

    half3 brdf = brdfData.diffuse;
#ifndef _SPECULARHIGHLIGHTS_OFF
    [branch] if (!specularHighlightsOff)
    {
        brdf += brdfData.specular * DirectBRDFSpecular(brdfData, normalWS, lightDirectionWS, viewDirectionWS);

#if defined(_CLEARCOAT) || defined(_CLEARCOATMAP)
        // Clear coat evaluates the specular a second timw and has some common terms with the base specular.
        // We rely on the compiler to merge these and compute them only once.
        half brdfCoat = kDielectricSpec.r * DirectBRDFSpecular(brdfDataClearCoat, normalWS, lightDirectionWS, viewDirectionWS);

            // Mix clear coat and base layer using khronos glTF recommended formula
            // https://github.com/KhronosGroup/glTF/blob/master/extensions/2.0/Khronos/KHR_materials_clearcoat/README.md
            // Use NoV for direct too instead of LoH as an optimization (NoV is light invariant).
            half NoV = saturate(dot(normalWS, viewDirectionWS));
            // Use slightly simpler fresnelTerm (Pow4 vs Pow5) as a small optimization.
            // It is matching fresnel used in the GI/Env, so should produce a consistent clear coat blend (env vs. direct)
            half coatFresnel = kDielectricSpec.x + kDielectricSpec.a * Pow4(1.0 - NoV);

        brdf = brdf * (1.0 - clearCoatMask * coatFresnel) + brdfCoat * clearCoatMask;
#endif // _CLEARCOAT
    }
#endif // _SPECULARHIGHLIGHTS_OFF

    return brdf * radiance;
}

  3. brdf高光项比较复杂，传统的就是CookTorrance的模型，不过Unity对其做了一些优化和曲线拟合，和传统的PBR有所不同：

    brdf += brdfData.specular * DirectBRDFSpecular(brdfData, normalWS, lightDirectionWS, viewDirectionWS);

    其核心函数就是DirectBRDFSpecular：

    // Computes the scalar specular term for Minimalist CookTorrance BRDF
// NOTE: needs to be multiplied with reflectance f0, i.e. specular color to complete
half DirectBRDFSpecular(BRDFData brdfData, half3 normalWS, half3 lightDirectionWS, half3 viewDirectionWS)
{
    float3 lightDirectionWSFloat3 = float3(lightDirectionWS);
    float3 halfDir = SafeNormalize(lightDirectionWSFloat3 + float3(viewDirectionWS));

    float NoH = saturate(dot(float3(normalWS), halfDir));
    half LoH = half(saturate(dot(lightDirectionWSFloat3, halfDir)));

    // GGX Distribution multiplied by combined approximation of Visibility and Fresnel
    // BRDFspec = (D * V * F) / 4.0
    // D = roughness^2 / ( NoH^2 * (roughness^2 - 1) + 1 )^2
    // V * F = 1.0 / ( LoH^2 * (roughness + 0.5) )
    // See "Optimizing PBR for Mobile" from Siggraph 2015 moving mobile graphics course
    // https://community.arm.com/events/1155

    // Final BRDFspec = roughness^2 / ( NoH^2 * (roughness^2 - 1) + 1 )^2 * (LoH^2 * (roughness + 0.5) * 4.0)
    // We further optimize a few light invariant terms
    // brdfData.normalizationTerm = (roughness + 0.5) * 4.0 rewritten as roughness * 4.0 + 2.0 to a fit a MAD.
    float d = NoH * NoH * brdfData.roughness2MinusOne + 1.00001f;

    half LoH2 = LoH * LoH;
    half specularTerm = brdfData.roughness2 / ((d * d) * max(0.1h, LoH2) * brdfData.normalizationTerm);

    // On platforms where half actually means something, the denominator has a risk of overflow
    // clamp below was added specifically to "fix" that, but dx compiler (we convert bytecode to metal/gles)
    // sees that specularTerm have only non-negative terms, so it skips max(0,..) in clamp (leaving only min(100,...))
#if REAL_IS_HALF
    specularTerm = specularTerm - HALF_MIN;
    // Update: Conservative bump from 100.0 to 1000.0 to better match the full float specular look.
    // Roughly 65504.0 / 32*2 == 1023.5,
    // or HALF_MAX / ((mobile) MAX_VISIBLE_LIGHTS * 2),
    // to reserve half of the per light range for specular and half for diffuse + indirect + emissive.
    specularTerm = clamp(specularTerm, 0.0, 1000.0); // Prevent FP16 overflow on mobiles
#endif

    return specularTerm;
}

     我们首先可以注意到注释中的D项目，它就是GGX中的D项计算，只是没有除以$\pi$，这是Unity故意去掉的，让整体画面看起来亮一些。

     V*F也就是G*F，这是拟合的近似公式:$\frac{1}{max((l·h)^2,0.1)(roughness+0.5)}$.

     在官方介绍的文档中$V = \frac{G(n·v,n·l,roughness)}{(n·v)(n·l)}$。G用的就是$G_{sksm} = \frac{(n·l)(n·v)}{lerp(roughness^2,1,(l·h)^2)}$，因此$V = \frac{1}{lerp(roughness,1,(l·h)^2)}$.

     $F = (1-(l·h))^5$.
     那么$V·F = \frac{(1-(l·h)^5)}{(l·h)^2(1-roughness^2)+roughness^2}$.

     当(l·h)接近1的时候，曲线会呈现平坦状态，当l与h角度接近90度也就是为0时候，曲线倾斜度非常剧烈，光线掠过表面并几乎与相机方向相反照射，斜率会迅速增加。
     本来这样的优化就是对移动端进行操作的，Unity又进行了魔改成最后的曲线：$(V·F) = \frac{1}{(l·h)^2 * (roughness + 0.5)}$，这样的曲线变化率变得更高了，也导致看起来的高光很亮，但在移动端看起来还是可以的，这样的优化极大增加了渲染的效率，所以Unity内置的并不算是完全物理的，有很多近似的地方在里面。

    🐍 为什么会推导出G_sksm这样的函数出来呢？

     参考连接: https://community.arm.com/cfs-file/__key/communityserver-blogs-components-weblogfiles/00-00-00-20-66/siggraph2015_2D00_mmg_2D00_renaldas_2D00_notes.pdf
     原因是：$GGX$本身就是Smith模型：$G_{Smith} = \frac{(n·l)(n·v)}{lerp(k,1,(n·l))lerp(k,1,(n·v))}$，因为$V$和$G$的关系是提取了$f_{cook-torrance}$的分母并进行了约分，公式如下：
    $$
    \begin{align}
    V_{Smith} &= \frac{G_{Smith}}{(n·l)(n·v)}\\
    & = \frac{(n·l)(n·v)}{lerp(k,1,(n·l))lerp(k,1,(n·v))(n·l)(n·v)}\\
    & = \frac{1}{lerp(k,1,(n·l))lerp(k,1,(n·v))}
    \end{align}
    $$
     而有一种廉价的近似方法KSK，它原本的公式应该为：$G_{ksk原版}=\frac{2(n·h)^2}{(l·h)(v·h)}$，但Unity对移动端进行了优化，$G_{ksk优化}=\frac{(n·l)(n·v)}{(l·h)^2}$，保留原本的ksk模型可以在PC上更加高效的物理计算，我们这里并没有处理。因此$V_{ksk} = \frac{1}{(l·h)^2}$。
     但是这样的模型缺少了粗糙度控制，后面J.Hable对其进行了改造，则变成了$V_{sksm} = \frac{1}{(l·h)^2(1-roughness^2)+roughness^2}$ ，所以这也是$G_{sksm}$的由来。

    注意：公式推导的roughness与代码中的roughnes不一样，代码中的roughness是Untiy做了预处理，是公式推导的roughness的平法。
