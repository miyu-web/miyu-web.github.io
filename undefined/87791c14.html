（二）Blender中自发光Emission节点算法详解

更新于2026-04-27
|总字数:1.3k|阅读时长:5分钟|浏览量:

前言

我们知道，着色器节点在Blender中是不可或缺的，不同的着色器节点可以实现不同的视觉效果，而这种不同之处就取决于它们底层实现的算法不同，此篇将以自发光Emssion节点解析为主。

什么是自发光

Emission，自发光，如字义，就是自身能够发光的物体。在三维世界中，我们要看见物体，一定是需要光经过反射，然后反射到人眼才能看见的。而光作为三维世界中的重要属性，其由光源，自发光之分。
光源不必多说，如日光，面光，点光这类本身就是发光源的。而自发光则是对于世界物体来说的，它本身也算是一个强度不是很高的光源，但我们还是会将其与光源单独分开。
在一般的游戏引擎中，光源会作为直接数据作为传输，传输到各种着色计算里，而对于自发光的物体，因为它本身不算做是光源（因为它没用固定的形状，发光效果，很难本模块化定义），因此一般做法就是渲染一张自发光烘焙图然后参与后续计算（因为自发光的物体要能对周围物体产生光效效果，只好这么做）。

很显然我们能看到，这里的计算核心就是：

Emission=(Strength*Color)*emission();

  • Strength：强度。
  • Color：颜色。
  • emission：基于Lambertian计算的自发光。

#include "stdcycles.h"

shader node_emission(color Color = 0.8, float Strength = 1.0, output closure color Emission = 0)
{
  Emission = (Strength * Color) * emission();
}

/* BACKGROUND CLOSURE */

ccl_device void background_setup(ccl_private ShaderData *sd, const Spectrum weight)
{
  if (sd->flag & SD_EMISSION) {
    sd->closure_emission_background += weight;
  }
  else {
    sd->flag |= SD_EMISSION;
    sd->closure_emission_background = weight;
  }
}

/* EMISSION CLOSURE */

ccl_device void emission_setup(ccl_private ShaderData *sd, const Spectrum weight)
{
  if (sd->flag & SD_EMISSION) {
    sd->closure_emission_background += weight;
  }
  else {
    sd->flag |= SD_EMISSION;
    sd->closure_emission_background = weight;
  }
}

/* return the probability distribution function in the direction wi,
 * given the parameters and the light's surface normal.  This MUST match
 * the PDF computed by sample(). */
ccl_device float emissive_pdf(const float3 Ng, const float3 wi)
{
  const float cosNI = fabsf(dot(Ng, wi));
  return (cosNI > 0.0f) ? 1.0f : 0.0f;
}

ccl_device void emissive_sample(const float3 Ng,
                                const float randu,
                                const float randv,
                                ccl_private float3 *wi,
                                ccl_private float *pdf)
{

}

ccl_device Spectrum emissive_simple_eval(const float3 Ng, const float3 wi)
{
  const float res = emissive_pdf(Ng, wi);

  return make_spectrum(res);
}

CCL_NAMESPACE_END

我们核心需要看的就是emissive_pdf函数，其中就是很简单的计算了一下兰伯特，然后将超过0的部分设置为1，低于0的部分设置为0，因为低于0的部分是没用光的，这算是计算了一个遮罩区域，将能被光照到的部分设置为1，没有光找到的部分设置为0，但是我们需要注意的是，这里的光实际指代的是视线方向，也就是摄像机到着色点的方向，而不是我们常规意义上的灯光方向，因为这是自发光计算。
Blender这样做也很好理解，就是将能看见的部分设置为1，看不见的部分设置为0，大家需要注意这一点。

ccl_device float emissive_pdf(const float3 Ng, const float3 wi)
{
  const float cosNI = fabsf(dot(Ng, wi));
  return (cosNI > 0.0f) ? 1.0f : 0.0f;
}

Blender在许多计算中都将wi指代为视线方向，wo指代为光源方向

自定义osl代码实现

使用emission闭包函数

首先要注意的时，此闭包函数已经被弃用，OSL官方说明在2.0将被舍弃，所以要注意一下OSL版本。

shader m_emssion(color Color=1,float strength=1,output closure color outColor=0)
{
    outColor=strength*Color*emission();
}

自定义脚本函数

shader m_emssion(color Color=1,normal Normal=N,float strength=1,output color outColor=0)
{
    float mask = abs(dot(Normal,I))>0.0?1.0:0.0;
    outColor=strength*Color*mask;
}

其中I是OSL内置的全局变量，指代的是视线方向。
